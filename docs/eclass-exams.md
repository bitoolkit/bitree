# 延河课堂测试导入

## 接口与认证

测试列表与学习活动是两个独立的数据源。课程列表仍复用现有的
`POST /api/my-courses`；每门课额外请求：

```http
GET /api/courses/{courseId}/exam-list?page=1&page_size=100
Accept: application/json
```

复用 `SchoolSession` 的 Cookie 存储、请求并发上限、取消和登录失效处理。
不得在源码、测试或文档中保存真实的 Cookie、令牌、姓名或原始抓包。

实测省略前端的 `conditions`、`reloadPage` 参数仍能获取列表；默认排序可能
与前端章节排序不同，导入不依赖返回顺序。

响应为：

```json
{
  "page": 1,
  "page_size": 100,
  "pages": 1,
  "total": 1,
  "start": 1,
  "end": 1,
  "exams": [
    {
      "id": 123,
      "type": "exam",
      "title": "示例测试",
      "start_time": "2026-11-01T00:00:00Z",
      "end_time": "2026-11-08T14:30:00Z",
      "submission_count": 0
    }
  ]
}
```

从第一页开始，按 `pages` 结束；缺失时使用每页条数收敛，空页总是结束。
没有测试的课程返回 `exams: []`。活动和测试分别容错，不因其中一路普通
接口错误丢掉另一路的结果；取消和登录失效仍向上传递。

## 映射规则

- 测试 ID 使用 `eclass-exam-{id}`；保留既有活动 ID `eclass-{id}`，避免两种
  资源编号相同导致覆盖，也避免迁移时重建已有作业。
- `end_time` 非空时作为截止时间，沿用北京时间墙上时钟转换。
- 无 `end_time`、有 `start_time` 时导入 `startOnly: true` 的日程，日期是
  开放时间而不是伪造的截止时间；不应显示逾期。
- 开始和截止时间均缺失时跳过，不能用同步时间制造不稳定日期。
- `submission_count > 0` 表示已提交；不使用 `is_closed`、成绩或
  `submit_times` 代替提交状态。补考字段的完成语义尚未验证，不作假设。
- 链接指向 `/course/{courseId}/exam`；未验证单个测试的安全详情跳转路径，
  不自动进入答题或启动限时测试。
- 无截止日期日程使用与普通 DDL 相同的占位及渲染宽度规则，但以开始时间
  为左边界，标线在左侧，背景向右侧淡出。
- 时间轴纵向滚动范围取当前筛选数据的全局最高泳道；横向平移不改变
  纵向范围，稀疏时间段允许保留空白泳道。卡片仍只按二维视口裁剪创建。
  筛选、缩放或窗口尺寸改变导致范围缩小时，裁剪使用新范围内的有效偏移。

## 验证范围

接口分析时验证了课程级列表、分页参数、UTC 时间与页面北京时间显示的
对应关系，以及提交计数与页面“未交”状态的对应关系。未假定匿名访问、
独立 Cookie 的必要性或补考行为；认证继续完全交由现有会话实现。

自动化回归覆盖接口分页、资源 ID 碰撞、完成状态、无截止时间、空列表、
独立容错，以及日程模型和时间轴布局。无本地 Flutter 环境时，由 GitHub
Actions 的 Linux x64 测试步骤运行；静态检查或推送成功不等于测试通过。
