# 日程完成与考试自动一次

## 完成和时间结束分离

`done` 表示真正的完成选择；`isFinished(now)` 保持旧调用接口但统一返回
`done`，不再用时间经过代替完成。`hasEnded(now)` 单独表示时间边界已到。

- DDL 沿用原有完成规则；逾期使用有效截止（含伪提前），仍是严格晚于截止。
- 仅开始时间的 DDL 可以完成，但没有截止时间，永不逾期。
- 普通日程不会自动完成；到真实结束时仍未完成即为逾期。
- 考试到真实结束时自动完成一次。用户手动完成或撤销也会消费这次自动机会，
  因而提前手动完成再撤销也不会在结束时覆盖人工选择。
- 考试自动完成后撤销，保持未完成并在真实结束后显示逾期；构建、重启、
  同 ID 同步和编辑不会再次自动完成。

伪提前只用于 DDL，不移动普通日程或考试的真实时间。

## 持久化与迁移

新增 `examAutoCompletionHandled`（默认 false）记忆自动机会是否消费，
`completionSchemaVersion`（当前 1）标识一次性历史迁移。新建日程直接使用
当前版本；旧 JSON 缺字段时读取为版本 0，解析本身不调用当前时钟。

控制器在加载后的可控时钟处迁移并原子保存：旧已结束普通日程标为完成以
保留原“已结束”历史效果；旧未来普通日程只升级版本，不自动完成。旧已完成
考试消费自动机会；未处理的到期考试原子写入 `done=true` 和 handled=true。
版本写回后，撤销不会被下一次加载当作旧数据重新完成。

自动与人工操作共用串行队列。人工操作使用 ID 和目标完成值更新最新记录，
避免旧 UI 快照覆盖同步元数据，也不在排队结束时反转最新值。写入失败不
发布已消费标记，保留重试机会；未处理的考试在补账失败期间不显示逾期。

## 时钟与生命周期

生产环境由 AppController 激活前台完成时钟，AgendaController 只持有一个
定时器，指向最近未处理考试的结束时间。暂停/后台取消，恢复前台补账；
关闭 App 后错过的结束时间在下次加载补处理，无需常驻后台任务。失败时
前台最短 30 秒重试，不能对过去的结束时间建立零延时写入循环。

测试可注入时钟。通用 TestAppController 默认关闭后台计时，生产时钟测试
显式开启并在测试正文结束前销毁，不能依赖晚于 Flutter 校验的 teardown。

## 同步、编辑与边界

同 ID 学校考试刷新时间、地点等元数据时，保留本地 done、handled 和版本；
单纯完成不把整条记录标为 local，避免阻断之后的远端内容更新。编辑器保留
这些状态字段。DDL 来源原有的远端提交状态策略不改变。

当前学校考试 ID 包含开始时间，远端改开始时间会生成新 ID。在没有可靠
稳定业务 ID 时不按标题猜配，多场考试不能误合并。因此当前只保证可匹配
的存续同 ID 记录保留选择；不同 ID 是新记录，物理删除/远端消失后重现也
没有额外的完成 ledger。扩展跨 ID 保留必须先取得可靠身份和迁移策略。

列表、详情、课表角标及提醒使用统一完成/逾期状态；学业考试页“过去考试”
和冲突判断仍使用真实时间是否结束，不能因提前手动完成而隐藏未来冲突。
非 DDL 删除仍采用原来的物理删除+即时撤销，不扩展 DDL 专用回收站范围。

Android 日程小组件只读 agenda.json：未完成逾期日程和已撤销考试不因
结束时间再次被隐藏；未处理到期考试和旧历史日程可只读派生原兼容状态，
仅 Dart 持久化迁移，不让两个运行时同时重写 JSON。学校课程下课过滤不变，
下一次刷新只选未来边界，避免过去时间造成刷新循环。
